## 1. Внутренняя кросс-проверка

Полностью просмотрены 100 карточек. Найдена одна пара одноимённых ООО «ЛЗСО»:
7805327192 и 4720028039. Между ними пять оснований связи: действующий учредитель,
руководитель, взаимная relatedCompanies-ссылка и две общие ссылки на внешние
организации. Взаимные ссылки не дублируются. Совпадение названия не используется.
Поддержаны также пересечение ролей, прямое владение и совпадения адреса, email,
сайта и телефона. В этом наборе совпадений контактов нет.

Full check автоматически получает связи и краткий срез соседей из PostgreSQL:
никаких дополнительных запросов к модели и полных отчётов для каждого соседа.
Использованы существующие finance/legal builders. Краткий срез содержит факты,
даты, пути к полям и пробелы. У соседа 4720028039 найдены ограничительные сигналы
источника, включая блокировку ФНС и недостоверность регистрационных сведений.
Они не присваиваются основной компании.

Ограничения: один шаг от основной компании, до шести соседей / 30 рёбер,
10 000 кандидатных карточек и четыре секунды I/O. Частичный/недоступный поиск
помечается явно; за пределами датасета отсутствие связей не утверждается.
Краткий обзор не является гарантией благонадёжности.

## 2. Граф

Если рёбер больше двух, backend гарантирует предложение в тексте и кнопку
«Построить граф связей». Запрос «Построй граф связей» строит канву из trusted
context, без model/tool calls. Перетаскивание узлов, масштаб, сброс, выбор
клавиатурой и список компаний; у каждого ребра раскрываются основания и поля.
У узла есть краткий обзор, пробелы и кнопка «Отдельный отчёт» с проверенным ИНН.

«Сделай отдельный отчёт по связанной компании» работает без повторения ИНН,
если сосед единственный. При нескольких соседях агент просит ИНН и не запускает
проверку произвольной компании. Активная компания меняется только при запросе
нового отчёта. Новые карточки не раскрываются каскадно автоматически.

## 3. Роза ветров

В том же ответе Master выбирает качественные уровни по финансам, судам,
взысканиям и регуляторным рискам, с краткими объяснениями. Зелёный разрешён;
обычный суд, небольшой платёж или молодой возраст не требуют красного.
Нет принудительного зелёного ради картинки. Недостаточные данные/недоступная
оценка — серые; официальные ограничительные сигналы не смягчаются кодом.

Профиль подписан «Мнение AI», причины раскрываются по нажатию. Это не числовой
рейтинг, вероятность дефолта или новая банковская оценка. Банк и ЗСК независимы.
Профиль появляется только в мини-дашборде full check, не в каждом follow-up.

## 4. Статусы

Frontend получает NDJSON-поток публичных этапов: принятие запроса, карточка,
анализ, сверка, поиск пересечений, обзор соседей, синтез. Для контекста, финансов,
сравнения и графа — свои этапы. Они соответствуют выполняющемуся коду; текст
Master приходит целиком. Heartbeat поддерживает соединение без фиктивных этапов.
События разных запросов изолированы; разрыв соединения отменяет coroutine.
Обычный POST /api/v1/chat/messages и legacy /api/v1/checks, /report сохранены.

### Живой финальный smoke

Рабочий Master: `z-ai/glm-5.3-flash` через OpenRouter. Доменные блоки используют
настроенный Groq. Прогоны последовательные, без retries; все ответы получены.

| Запрос | Время HTTP | Model calls | Domain calls | Результат |
|---|---:|---:|---:|---|
| Проверь 7805327192 | 25,98 с | 1 | 1 | Связи и краткий обзор; семь статусов |
| Построй граф связей | 0,02 с | 0 | 0 | Два узла, пять рёбер; backend 6 мс |
| Отчёт по связанной компании без ИНН | 23,60 с | 2 | 1 | Правильно выбран 4720028039 |
| Проверь 1684017097 | 39,11 с | 1 | 1 | Финансы low; другие направления unknown |

В полном ответе модель описала связи и оговорила, что показатели соседа не
переносятся на основную компанию. В первой пробе нулевая выручка оказалась
сгруппирована со стоп-факторами; инструкция уточнена, в финальной пробе прямо
отмечено, что нулевая выручка/пробелы сами по себе не стоп-факторы. Содержательная
аналитика остаётся интерпретацией модели: эти проверки не доказывают абсолютную
точность всех возможных ответов. Grounding debug/verifier остался в прежнем
production-режиме (выключен), структурная валидация продолжает работать.

Сырые ответы и события локально: `output/playwright/night-live.json`.
Скриншоты: `output/playwright/radar-desktop.png`, `radar-mobile.png`,
`connections-mobile.png`. Артефакты проверки исключены из Git.

## DB impact и запуск

Добавлена read-only view `core.v_connection_candidates`; таблицы и данные не
переписываются. Миграция: `backend/db/migrations/003_connection_candidates.sql`,
также включена в schema.sql для новых БД. В текущей Docker-БД уже применена.
При развёртывании на другой существующей БД выполнить миграцию перед рестартом
API. Новые поля JSON/Pydantic необязательные, старые ответы совместимы.

```sh
docker exec -i contractors-db psql -U postgres -d contractors -v ON_ERROR_STOP=1 < backend/db/migrations/003_connection_candidates.sql
docker compose -f backend/docker-compose.yml up -d --build api
python3 backend/scripts/smoke_night_features.py --output /tmp/night-live.json
```

Smoke расходует токены настроенных моделей; не запускать как частый unit test.
После пересборки сервиса старые in-memory диалоги истекают: начните новый диалог.

## Ручная приёмка

1. Открыть http://localhost:8000, обновить страницу и нажать «Новый диалог».
2. Отправить «Проверь контрагента 7805327192»: увидеть меняющиеся статусы,
   мини-дашборд, краткое упоминание 4720028039 и предложение графа.
3. Построить граф, выбрать узел 4720028039, раскрыть основания/пробелы;
   нажать «Отдельный отчёт» или попросить его сообщением без повторения ИНН.
4. В новом диалоге проверить 1684017097, раскрыть «Мнение AI · почему?».
   Уровни модели могут различаться между прогонами; принудительного зелёного нет.
5. Открыть «Полный анализ», проверить привычный legacy-отчёт. На реальном телефоне
   дополнительно проверить жесты и системную клавиатуру: viewport-эмуляция их не заменяет.
