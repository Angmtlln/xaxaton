# Поиск по деятельности и финансовым условиям

`find_companies` фильтрует текущую загруженную базу одновременно по деятельности
и финансовым/правовым условиям. Основные **и дополнительные ОКВЭД учитываются
по умолчанию**, по пожеланию пользователя. Для компании достаточно одного
подходящего кода; несколько совпадений не увеличивают счётчик компаний.

## Использование

- «Найди компании занимающиеся торговлей и с выручкой от 10 млн».
- «Найди компании занимающиеся оптовой торговлей фруктами и с выручкой от 10 млн, покажи первые 5».
- «Найди компании с ОКВЭД 46.7 и с выручкой от 10 млн».
- «Найди компании занимающиеся торговлей только основной ОКВЭД» — явное ограничение основным видом.

Эти целиком распознанные команды вызывают SQL напрямую; модель формирует
объяснение по результату. Сложные формулировки остаются в существующем native
маршруте. Явно названная через «занимающиеся …» / «по деятельности …» деятельность
закрепляется backend и не исчезает, даже если модель передаст только выручку.
Применённые условия показываются над таблицей. Совпавшие коды и описания
сохраняются в проверенных данных backend, но не выводятся в строках таблицы.

## Источник и ограничения

Источник JSON: `report.kindsOfActivityInfo.mainKindOfActivity.{code,description}`
и `otherKindsOfActivity[].{code,description}`. Загрузчик уже сохраняет их в
`core.activity_codes`: 100 основных записей, 2128 дополнительных у 97 компаний
в локальном наборе, проверенном 6 сентября 2026.

Отдельная полная копия классификатора не добавлена. Словарь здесь — реальные
названия ОКВЭД из загруженных снимков. Поиск использует PostgreSQL full-text
с конфигурацией `russian`: «торговля» и «торговлей» совпадают. Все значимые слова
должны совпасть в описании одного кода, а не в разных дополнительных видах.
Это лексический поиск со словоформами, не универсальный поиск синонимов:
произвольные разговорные названия отраслей могут не найтись. Код пользователя
ищется вместе с дочерними кодами: 46.7 включает 46.73 и 46.73.1.

ОКВЭД показывает заявленную деятельность, не доказывает фактические продажи.
Порог выручки относится ко всей компании за её последний доступный финансовый
год, а не к выручке конкретного направления. Отсутствующие ОКВЭД/описания не
считаются совпадением. Пустая подборка не приводит к поиску без фильтра.
Альтернативы/исключения вроде «не торговля» пока не поддерживаются.

## DB impact и запуск

Новая идемпотентная миграция `005_shortlist_activity.sql` добавляет `snapshot_id`
в существующую read-only view. Таблицы и исходные карточки не изменяются.
Для новой базы это же определение включено в `schema.sql`.

```bash
docker exec -i contractors-db psql -U postgres -d contractors -v ON_ERROR_STOP=1 \
  < backend/db/migrations/005_shortlist_activity.sql
docker compose -f backend/docker-compose.yml up -d --build api
```

Миграция применена к локальной Docker БД. Фильтрация через EXISTS выполняется
до count/order/limit, поэтому финансовые условия и деятельность соединяются
через AND без дублей. Значения параметризованы; SQL-операторы из запроса не исполняются.

## Проверки

227 passed: shortlist, comparison, runtime, chat UX/API, multiturn, latency,
legacy pipeline, response, targeted response. PostgreSQL integration — 2 passed:
комбинация условий, дополнительный код при другом основном, main-only,
подкоды, отсутствие дублей до LIMIT, нулевой результат, отсутствие данных.
`node --check` и `git diff --check` без ошибок.

На текущей БД с mock LLM: торговля + выручка от 10 млн — 43 компании;
лимиты 10 и 25 соблюдены, без фильтра деятельности было 51.
По запросу про разведение верблюдов получена пустая подборка.
Это проверка SQL/контракта; качество свободного ответа модели проверяется отдельно.

Ручная проверка на desktop: выполнить первый запрос, проверить компактную таблицу,
сравнить выдачу с суффиксом «только основной ОКВЭД», задать «Объясни проще».
Мобильная версия остаётся на паузе.


Живой runtime с OpenRouter `z-ai/glm-5.3-flash`: запрос про торговлю и выручку
от 10 млн, первые 5 — 43 совпадения / 5 строк; 1 tool / 1 model call,
6,6 с, synthesis=model, без fallback. `grounding_status=not_requested`:
проверена работа фильтров и ответа, не достоверность каждого свободного вывода.

Техническая документация используемого поиска:
[PostgreSQL 16: управление текстовым поиском](https://www.postgresql.org/docs/16/textsearch-controls.html).
