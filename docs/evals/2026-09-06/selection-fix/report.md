# Исправления подбора и актуальности снимков

Работа начата 6 сентября, завершена 7 сентября 2026 по Москве.

## Причины и изменения

Сбой MCP-приёмки воспроизведён на рабочем API: `ReviewBatch.reviews.0.summary`
превысил 450 символов. Результат до исправления — [before.json](before.json),
`partial`, 2 model calls, 13,600 с. Данные через MCP были получены правильно.

- Мини-сводкам задан более короткий целевой объём. Только для превышения длины
  текстовых полей разрешена одна попытка сокращения на весь ход, внутри прежних
  8 model calls и deadline. Остальные поля должны остаться неизменными; проверки
  ИНН, evidence и состава кандидатов не ослаблены. Попытка отражается в metadata.
- Запрос «подбери … для поставок» попадает в подбор. Условия сделки не становятся
  фильтром деятельности/названия, роль определяется по смыслу пользовательской цели.
- При нуле/одном финалисте итоговая модель возвращает только объяснение: поля
  сортировки нет. Отказ рекомендовать единственного кандидата — завершённый подбор,
  а не ошибка. При нескольких финалистах проверка точной перестановки сохранена.
- Методология `0.3.6-snapshot-freshness` различает дату снимка и дату обращения:
  старый статус нельзя объявлять подтверждённым сегодня. Подбор сохраняет роли
  сторон сделки и не рекомендует аванс поставщику как защиту при условии «без аванса».

DB impact отсутствует: изменены только внутренние контракты ответа LLM,
инструкции и обработка результата; таблицы, SQL и исходные данные не менялись.

## Автоматические проверки

Финальный регрессионный набор — **195 passed**, одно существующее предупреждение
AnyIO. Проверяются подбор, routing, grounding behavior, ranking, поиск, runtime,
multi-turn и chat API. Новые сценарии включают восстановление после длинного
обзора, отклонение изменения ИНН/evidence, повторной ошибки и превышения бюджета,
успешное объяснение отсутствия финалистов, сохранение обычного поиска деятельности.

```bash
cd backend
PYTHONPATH=.:tests .venv/bin/python -m pytest -q \
  tests/test_counterparty_selection.py tests/test_agent_request_routing.py \
  tests/test_grounding_behavior.py tests/test_ranking.py tests/test_shortlist.py \
  tests/test_agent_runtime.py tests/test_agent_multiturn.py tests/test_chat_api.py
```

## Живые проверки

Рабочий Docker API, реальный MCP/PostgreSQL, OpenRouter `z-ai/glm-5.3-flash`.
Запросы и ответы сохранены дословно; `AGENT_EVALS.md` не менялся.

- [Подбор и «Объясни проще»](selection.json): исходная формулировка из MCP-smoke,
  финальный код. Оба ответа `completed`, synthesis=model, без fallback.
  Подбор — 4 model / 1 tool, 18,020 с; объяснение — 2 model / 0 tools, 3,010 с.
  Найдена и рассмотрена одна компания; отказ рекомендовать её объяснён.
  Вручную проверены условия без аванса, направление поставки, отсутствие
  гарантии оплаты и привязка статусов к снимку. В этом проходе сокращение
  не понадобилось; принудительная ошибка длины проверяется unit-тестами.
- [Явный запрос одного поставщика](selection-explicit.json): завершён без fallback,
  4 model / 1 tool, 38,475 с. Найдена и рассмотрена одна компания; отсутствие
  финалистов объяснено. Этот прогон предшествует последнему уточнению ролей сделки.
- [Актуальность и объяснение](freshness.json): на вопрос о блокировке сегодня
  модель прямо сказала, что подтвердить её не может, указала дату снимка и
  объяснила, что повторное чтение не обновляет источник. «Объясни проще» сохранило
  оговорку. Оба продолжения — 0 tools / 1 model, 56,715 и 68,405 с.
  Дата источника независимо сверена REST: `2026-08-09T21:00:00+00:00`.

Первый полный анализ в этом сценарии и [отдельный повтор](full-final.json)
завершились безопасным fallback после 90-секундного timeout вызова Master.
MCP и доменная проверка отработали. Успешный новый полный текст анализа с web
plugin этими повторами не подтверждён; timeout не скрыт успешными уточнениями.
Провайдер, модель и таймауты ради прохождения проверки не менялись.

Промежуточные результаты сохранены отдельно:
[лишнее уточнение роли](routing-initial.json),
[ошибка итогового контракта](selection-intermediate.json),
[подбор до уточнения ролей сделки](selection-before-role-fix.json).
В последнем обнаружено предложение предоплаты поставщику, противоречащее условию
пользователя; после этого добавлено правило о направлении поставки и оплаты.
В [следующей пробе](selection-before-payment-clarification.json) модель ошибочно
приравняла отсутствие аванса к исключённой неоплате пользователем. Последнее
уточнение явно разделяет эти понятия; платёжеспособность пользователя неизвестна.

`grounding_status=not_requested` у модельных ответов не означает доказанную
корректность всей прозы. Исправление длины — проверка формата, не семантический
верификатор. Универсальная безошибочность рекомендаций не заявляется.

## Как проверить вручную

После обновления API открыть новый диалог и повторить запросы из JSON-файлов.
Проверить соблюдение выручки от 10 млрд, объяснение отказа при отсутствии
подходящих финалистов, сохранение условия без аванса и оговорки о дате снимка.
