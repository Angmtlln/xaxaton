# MCP: приёмка 06.09.2026

MCP-путь реализован и проверен через отдельный HTTP-сервер и PostgreSQL.
Docker использует `mcp`; прямое чтение доступно только при явном переключении.
Транспортная приёмка успешна. Живой подбор завершился частично из-за ответа
модели; успешность MCP не означает успешную семантическую приёмку агента.

## Среда и объём

- Docker: Python 3.11, PostgreSQL 16, официальный `mcp==2.1.1`.
- MCP: Streamable HTTP, stateless JSON, `company-data-v1`, семь tools.
- Изолированная временная БД: 100 карточек из текущей выгрузки; отдельный
  MCP-процесс, официальный клиент, реальные SQL и роль `contractors_mcp`.
- Рабочий Docker: тот же образ для API и MCP, отдельные окружения;
  MCP получает только собственный DB DSN. Локальный порт: `127.0.0.1:8001`.
- Изменения данных: служебные роли и GRANT; исходные карточки не менялись.
  Живая полная проверка создала обычный прогон аудита.

## Автоматические проверки

| Набор | Результат | Что подтверждает |
|---|---|---|
| Протокол + границы приложения | 17 passed (10 + 7) | Реальный MCP-процесс, discovery, схемы, Decimal/даты/JSON, отсутствие карточки, размеры, timeout, отмена, конкурентность; все шесть фасадов без direct bypass; REST и NDJSON |
| Изолированный PostgreSQL + MCP | 3 passed | Все 100 снимков и рассчитанные факты/coverage совпали; все шесть операций, фильтры/ranking/порядок/total/eligible_total; права; перезапуск и запись аудита |
| SQL каталога/подбора | 3 passed | Сохранена семантика существующих SQL-тестов после переноса reader |
| Pipeline, finance/legal, сравнение, поиск/ranking, подбор, связи, chat API + протокол | 245 passed | Узкая регрессия затронутых возможностей, включая протокольные тесты |
| Runtime, multi-turn, progress, response, targeted response + MCP | 89 passed | Контекст, ответы и ошибки агента, включая пересекающиеся MCP-тесты |

Числа пересекающихся запусков **не суммируются**. В финальный набор границ
приложения добавлен отдельный NDJSON-тест; он входит в указанные 7 тестов.
Предупреждения: существующее предупреждение AnyIO; при первом Docker-запуске
pytest не мог записать cache в read-only mount. Тесты от этого не падали.

Сверка 100 карточек строит факты детерминированно без LLM. Отдельный полный
`run_check(..., persist=True)` использует mock LLM, идёт через MCP и сохраняет
аудит, при этом локальный PostgreSQL reader API заменён функцией, которая
падает при вызове. Серверный reader выполняется в другом процессе.

Права проверены после `SET default_transaction_read_only=off`: чтение исходных
JSON разрешено; UPDATE/DELETE, создание таблицы в `core` и SELECT `audit.*`
отклоняются PostgreSQL. Setup выполнен дважды для проверки идемпотентности.

Команды быстрых и DB-тестов приведены в
[инструкции MCP](../../../MCP_DATA_ACCESS.md#проверки-и-границы-результата).

## Добавленная задержка

100 последовательных чтений снимков в изолированном Docker-тесте:

| Режим | Медиана | Максимум |
|---|---:|---:|
| Direct | 1,32 мс | 8,03 мс |
| MCP, новая сессия на каждое чтение | 21,66 мс | 210,75 мс |

Разница медиан — около 20 мс на чтение в этой среде. Это локальный замер,
не SLA и не нагрузочный тест; полная задержка чата зависит также от моделей.
В рабочем desktop-smoke отдельные MCP-чтения занимали примерно 0,1–0,2 с.

## Отказ и восстановление рабочего сервера

Временно остановлен только `company-data-mcp`; API и аудитная БД оставались
запущенными. Результаты сохранены в [outage.json](outage.json):

- `/health`: HTTP 200 с `status=degraded`, `database=true`,
  `data_source=mcp`, `data_source_available=false`.
- REST чтение фактов: HTTP 503 с безопасным сообщением источника.
- NDJSON: штатные progress/result, `status=error`,
  `error_code=source_unavailable`, ноль вызовов модели; компания не объявлена
  отсутствующей.
- После запуска MCP без перезапуска API: `/health` снова `ok`, чтение — 200.

Дополнительно реальный неизвестный ИНН вернул REST 404. Ошибочные ответы
источника и timeout проверены протокольными/API-тестами как 502/503.

Проверен и явный откат работающего Docker API `mcp → direct → mcp` с
пересозданием API: оба режима дали одинаковый REST-ответ фактов 7805327192,
health в каждом режиме был `ok`. После проверки восстановлен `mcp`, оба
сервиса запущены из пересобранного образа. Результат —
[mode-switch.json](mode-switch.json).

## Ручная приёмка после доставки

После настройки своего окружения проверить `/health`, открыть обычный чат,
запросить проверку, граф, сравнение и PDF. Для MCP-клиента использовать пример
из инструкции. На новых данных повторить подбор и отдельно оценить качество
прозы и рекомендации: текущие ошибки модели не устраняются сменой транспорта.
Подключение реальной системы заказчика и удалённая авторизация не входят в v1.
