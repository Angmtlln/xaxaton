# Semantic fixes: сравнение и answerability traps

## Результат и граница

Risk Playbook обновлён до **0.3.1**. Три целевые проблемы K17/K18/K20 прошли ручной разбор финального comparison-прогона. Это не полная поведенческая приёмка продукта: в K15 остаётся превращение нулевой выручки в установленную нулевую операционную активность.

Внесены только инструкции интерпретации и новая версия prompt. Расчёты, исходные данные, scenario bank, `AGENT_EVALS.md`, schema/SQL, routing, tools, UI и legacy flows не изменены. Runtime judge и проверки русской прозы регулярками не добавлялись. DB impact отсутствует.

## Почему исправлены инструкции

[Исходный разбор](before-review.json) содержит точные цитаты старых ответов, source references и проверенные входы расчётов для трёх реальных ИНН.

| Проблема | Что уже правильно передавал backend | Изменение |
|---|---|---|
| K17: «бесконечное» отношение к нулевой выручке | Для АПРЕЛЬ: 623 000 ₽ кредиторки, выручка 0; ratio=null, not_calculable/nonpositive_denominator | Сохранять неопределённость во всём ответе; не включать её в числовой рейтинг |
| K18: оценка числа кредиторов по судебной активности | В snapshot раскрыты суммы задолженности и количества событий, не количество уникальных кредиторов | Не выводить число лиц из amounts/event counts; предложить сумму как другой показатель |
| K20: малый масштаб отменяет legal-анализ | У АПРЕЛЬ есть юридические события и валидные отношения исков к активам/капиталу: 4,85%/5,74% | Сравнивать по новому критерию, различать абсолютную и относительную нагрузку; не предписывать победителя |

Первый вариант 0.3 исправил часть поведения, но выявил ошибки: K17 назвал 33,3% больше 57%, K20 заявил минимум «по всем измерениям» вопреки разным лидерам по абсолютной и относительной нагрузке. Эти ответы сохранены. В 0.3.1 добавлена сверка вывода с выбранным показателем и сохранение числителя/scope: отношение всех исков нельзя приписывать незавершённым.

## Проверки

**66 passed**: существующие тесты Risk Playbook, data coverage, comparison и eval harness. Они проверяют доставку канонической методологии, структуру и происхождение данных, маршрутизацию и целостность eval source. Проверки на совпадение прозы с ожидаемыми словами не добавлялись; содержательное поведение проверено live.

Финальная цепочка K15–K20: **6 технических PASS**, один `compare_companies`, пять продолжений без tools. Ручной review всех шести ответов: **5 PASS / 1 FAIL (K15)**. Целевые K17/K18/K20: **3 PASS**. Финальные K18 и S15_01 в traps также вручную проверены и прошли по границе количества кредиторов.

Финальный `traps`: **31/31 технических PASS**; вместе с подготовительными репликами и зависимостями — 69 turns. У двух setup-реплик превышен eval SLO 60 секунд: S15_06.setup1 — 111,6 s; S15_17.setup1 — 71,5 s. Они не входят в scored denominator и сохранены как FAIL latency.

| Версия | Comparison: технические PASS/FAIL | Traps: технические PASS/FAIL | Всего turns |
|---|---|---|---|
| 0.3, первая попытка | 6 / 0 | 31 / 0 | 75 |
| 0.3.1, финальная | 6 / 0 | 31 / 0 | 75 |

В первой попытке также сохранены три unscored FAIL latency. Хорошие технические результаты обеих попыток не скрывают обнаруженные semantic failures.

Ручной выборочный review финального traps: K18 и S15_01 прошли; **четыре подтверждённых FAIL** — K21 сглаживает реальный конфликт source narrative и цифр, S15_10 и S15_12 приписывают коэффициент всех исков только незавершённым, S15_18 выдаёт механизм финансирования за факт. Цитаты и source references сохранены. Выборка не случайная, поэтому её pass rate нельзя переносить на весь suite.

Eval-only judge оценил все 31 scored ответа: **29 provisional PASS / 1 FAIL (S15_18) / 1 JUDGE_ERROR (S15_12)**. Он пропустил ручные FAIL K21 и S15_10. В S15_12 judge сам отметил неверный коэффициент, но вернул PASS вместе с findings; harness правильно отверг несовместимый verdict. Эта попытка не перезапущена и не подменена PASS; ручная оценка S15_12 — FAIL. Автоматический FAIL S15_18 дополнительно указывает на ошибочное заявление об отсутствии учредителей в источнике.

Итог: три целевые проблемы прошли данный comparison-прогон, но **полная semantic-приёмка не пройдена**. Правила интерпретации улучшают наблюдаемое поведение, не гарантируя его во всех формулировках. Повторение ошибки числителя в traps и расхождения с judge — следующий предмет исправления и независимого review.

Ручной review выполнен coding agent, а не независимым человеком. Автоматическая оценка той же настроенной моделью является предварительной и не заменяет приёмку. Изменение победителя не является условием PASS: оценивается обоснование текущего критерия по `AGENT_EVALS.md`.

Из корня репозитория:

```bash
cd backend
PYTHONPATH=. .venv/bin/python -m pytest tests/test_risk_playbook.py tests/test_data_coverage.py tests/test_comparison.py tests/test_eval_harness.py -q
PYTHONPATH=. .venv/bin/python -m evals.run_local --suite killer --session K-comparison --concurrency 1 --output evals/results/semantic-comparison-replay
PYTHONPATH=. .venv/bin/python -m evals.run_local --suite traps --concurrency 3 --output evals/results/semantic-traps-replay
PYTHONPATH=. .venv/bin/python -m evals.judge --run evals/results/semantic-traps-replay --suite traps --concurrency 3
```

Live-команды требуют настроенных ключей и нового output-каталога. Для source-данных используется фиксированный snapshot вместо БД; `persist=False`. HTTP/UI и развёрнутый сервис не проверялись и не перезапускались. Вручную после загрузки новой версии backend: K15–K20 в одном новом чате, затем вопрос о количестве кредиторов; отдельно проверить оставшиеся semantic findings. Полный suite `full` в этой задаче не перезапускался.
