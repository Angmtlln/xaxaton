# Исправления данных без изменения prompt

## Результат

Исправлены три потери/неоднозначности данных: разные числители судебных
коэффициентов, скрытые финансовые комментарии источника и отсутствующие в
контексте учредители. Дополнительно уточнено значение двух полей баланса.
`prompt.py` и `RISK_PLAYBOOK.md` **побайтно совпадают с базой ea6f8ae**;
версия остаётся `master-risk-playbook-0.3.1`. Их SHA-256 сохранены в summary.

**89 тестов прошли. Финальные 10/10 реплик прошли технические проверки,
но ручной содержательный review: 4 PASS / 6 FAIL.** Это ограниченное
исправление доставки данных, а не завершённая semantic-приёмка продукта.
Первую попытку и её ошибки также сохранили; хороший ответ одного прогона
не использован вместо неудачного ответа следующего.

## Что изменилось

| Проблема | Исправление | Подтверждение / предел |
|---|---|---|
| Коэффициент всех исков приписывался только незавершённым | Backend отдельно считает отношения всех и pending исков к активам, капиталу и выручке; сохраняет role, stage, source path и год знаменателя | ГДК: 20 843 367 / 3 782 000 = **551,12%**; pending 18 894 669 / 3 782 000 = **499,59%**. В обеих live-попытках коэффициенты различаются правильно |
| K21 не получал финансовый комментарий после первых пяти общих маркеров | Full check отдельно передаёт исходные записи с chapter=finance и точными source indices; они сохраняются в finance follow-up | Обе попытки замечают «стабильный доход» при выручке 0 ₽. В финальной модель всё равно заканчивает «противоречия нет» — K21 остаётся FAIL |
| В контексте был только shareCapital, без участников | Добавлен cofounders с обычной пагинацией; данные сохраняются в finance follow-up и доступны через connections | Обе попытки называют реального участника ГДК и долю. Это не раскрывает фактических кредиторов и все потоки финансирования; S15_18 остаётся FAIL |
| totalLiabilities прочитан как сумма долгов | В finance_scope добавлены определения: все пассивы включают капитал; capitals не равен взносам собственников | Ошибка обнаружена в первой попытке S15_18 и не повторилась в финальной. Неподтверждённые выводы о финансировании собственником остались |

У АПРЕЛЬ значения Pending **неизвестны**, а не равны нулю. Backend сохраняет
missing и не восстанавливает их из годовых сумм. Все/pending не связываются
по году без общего ключа; иски и исполнительные производства не складываются.
Невалидная база коэффициента остаётся `not_calculable`.

Данные передаются через существующие capabilities и trusted context.
Новые LLM-этапы, runtime judge, семантические regex-проверки и собственный
скоринг не добавлялись. SQL, repository и модели БД не менялись; миграция
не требуется. Это расширение нормализованных DataSection, с сохранением
существующих имён полей. Legacy endpoints и UI-код не изменены.

`persist=False`. Source/snapshot/bank hashes находятся в каждом manifest.

отсутствие `result_too_large` на любых комбинациях компаний.

Это review coding agent, **не независимая человеческая приёмка**. Для первой
попытки содержательно размечены пять выбранных ответов; остальные сохранены
без общего semantic verdict. Setup проверены технически, но не получили
semantic verdict. Автоматический judge не запускался: текущий judge рассчитан
на полный suite; его проверки полноты не ослаблялись ради этой выборки.
Полный `full` и весь `traps` здесь не перезапускались.

89 тестов проверяют source-to-context путь, значения и provenance расчётов,
missing/invalid/zero границы, пагинацию участников, лимиты comparison,
multiturn, доставку playbook и chat API. Один прежний DeprecationWarning
Starlette/AnyIO сохранён в выводе. Тесты не являются доказательством
корректности свободного текста.

Live-команды требуют настроенных ключей и нового output-каталога.
HTTP/UI live-проход не запускался, развёрнутый сервис не перезапускался.
После загрузки новой версии backend вручную проверить в новых чатах:
сравнение трёх ИНН → относительная судебная нагрузка; проверку АПРЕЛЬ →
вопрос K21; проверку ГДК → «Кто финансирует эту компанию?». Проверять не
только наличие нужных данных, но и оговорки в итоговом выводе.

Следующий предмет работы — устойчивость рассуждения на уже правильно
переданных данных. В первую очередь missing стадий, source conflict в
заключении и разделение владения/баланса/потоков финансирования. Новыми
частными фразами в prompt эти остаточные ошибки в данной задаче не закрывались.
