# GLM и Claude на одинаковом контексте

## Вывод

**Простая замена GLM-5.3-Flash на Claude Sonnet 4.6 не показала общего
улучшения на проверенной выборке.** Claude реже нарушал границу неизвестных
стадий, но также скрывал конфликт источника и добавлял неподтверждённые
объяснения. Рабочая модель, `.env`, prompt, Risk Playbook и продуктовый код
оставлены без изменений. Исправление этих semantic failures не объявляется.

Добавлен только eval-only `evals.compare_models`: он позволяет повторять
контекстные реплики на разных моделях с одинаковыми входными сообщениями.
Новые продуктовые инструменты, verifier, regex-проверки прозы и LLM-этапы
не добавлялись. DB impact отсутствует; SQL/repository/schema не менялись.

## Эксперимент

Из [предыдущего прогона](../structured-scope-fix/report.md) взяты три проблемные
реплики без изменения вопроса или фикстуры:

- **K19:** судебная нагрузка относительно масштаба — missing Pending и
  необоснованное сведение всех дел к Finished.
- **K21:** позитивный финансовый комментарий при нулевой выручке — конфликт
  не должен исчезнуть в итоговом выводе.
- **S15_12:** «Кто обанкротится первым?» — повторная проверка missing Pending
  в другом аналитическом вопросе.

Источник критериев: [AGENT_EVALS.md](../../../../AGENT_EVALS.md), §0, ожидания
кейса, §19 и §20. Реальные компании: ГДК 6165169320, ЛИДЕРТЕКС 3711039473,
АПРЕЛЬ 7813664770. Банк и snapshot не менялись.

Каждый кейс выполнен **3 раза на каждой из 2 моделей: всего 18 ответов**.
Через существующий `create_agent` и checkpointer восстановлены исходные
trusted state и последние сообщения до целевой реплики. Каждая попытка
начинается с отдельного ConversationStore. Прежние ошибки в GLM-истории
сохранены для обеих моделей; в trusted data они не превращаются.

Фактические сообщения к моделям совпали **побайтно по каждому кейсу во всех
шести попытках** — подтверждено SHA-256. Данные Pending с missing и реальный
противоречивый финансовый комментарий присутствуют в переданном контексте.
На этом пути новой потери данных не обнаружено: ошибки возникают при
формировании ответа на уже доступные сведения.

Настройки обеих моделей одинаковые: OpenRouter, temperature=0,
reasoning effort=low, максимум 4096 output tokens, timeout 90 s,
provider sort=throughput. Это одинаковые параметры API, **не одинаковая
токенизация или внутренний вычислительный бюджет**. Модели проверены через
актуальный [каталог OpenRouter](https://openrouter.ai/api/v1/models).

Доменные вызовы и repository read в replay заблокированы. Это изоляция
рассуждения на сохранённом контексте; новые full-check/setup и маршрутизация
не оцениваются. Порядок моделей в очереди менялся между повторами,
одновременно выполнялись максимум две попытки.

## Результаты

| Проверка | GLM-5.3-Flash | Claude Sonnet 4.6 |
|---|---:|---:|
| Технические PASS | 9/9 | 9/9 |
| Ручной PASS всего ответа | **3/9** | **2/9** |
| Ручной FAIL всего ответа | 6/9 | 7/9 |
| Нарушение границы missing / полноты стадий, K19 + S15_12 | 3/6 | 1/6 |
| Скрытый или отрицаемый конфликт K21 | 1/3 | 1/3 |
| Медиана времени ответа | 9,92 s | 12,25 s |
| Максимум времени ответа | 18,52 s | 17,60 s |
| Input / output tokens, сумма 9 ответов | 208 410 / 4 467 | 252 732 / 8 281 |

Узкая целевая проверка и оценка всего ответа разделены: ответ может сохранить
missing, но выдумать причину или исказить другую цифру. PASS целевой границы
может означать, что ошибка не проявилась, а не что модель явно объяснила
неизвестность. Технические graders проверяют структуры, не истинность прозы.

Подтверждённые примеры:

- **GLM, S15_12, повтор 2:** «незавершённых исков нет». У АПРЕЛЬ Pending
  count/amount имеют missing. В двух ответах K19 также сказано «оба дела
  завершены» без оговорки: совпадение годового count и Finished count не
  даёт ключа для связывания агрегатов.
- **Claude, K19, повтор 2:** «Все 2 дела завершены» при той же неизвестной
  Pending-части. В повторе 1 соседняя оговорка «незавершённых не раскрыто»
  сохраняет неизвестность — этот пограничный случай размечен PASS с пояснением.
- **GLM, K21, повтор 3:** «Итог: противоречия нет» после описания позитивного
  комментария с нулевой выручкой.
- **Claude, K21, повтор 2:** «Расхождение между ними не ошибка — это два
  разных измерения». Конфликт финансового source marker полностью пропущен.
- **Claude, K21, повтор 1:** «триггер сработал на наличие записи». У нас есть
  текст источника, но нет реализации генератора; механизм придуман.
  Аналогичная неподтверждённая причинность встречается и у GLM.
- **Claude, K19, повтор 3:** «при нулевой выручке даже небольшие требования
  покрывать нечем». Выручка 0 не отменяет раскрытых активов и капитала.
- **GLM, K19, повтор 1:** 18 946 690 ₽ вместо проверенных 18 894 669 ₽
  незавершённых требований. Технический PASS не выявил ошибку внутри prose.

Review выполнил coding agent, **не независимый человек**. Все 18 ответов
прочитаны целиком; точные цитаты и обоснования находятся в machine-readable
review. Автоматический judge не использовался. Выборка мала и целевая;
разница 3/9 и 2/9 не доказывает статистическое или общее превосходство модели.

## Проверки, ограничения и воспроизведение

**14 tests passed**: целостность исходного банка, отказ от подмены вопросов,
запрет replay инструментальных реплик, проверка hash drift, восстановление
одинаковой истории/контекста, отсутствие domain calls и загрязнения одной
попытки результатом другой. Тесты не оценивают русскую прозу регулярками.

При заключительной проверке harness обнаружено, что replay не прикладывал
fixture contract к K21: проверка исходной фикстуры получала NA. Передача
контракта добавлена и проверена тестом; все сохранённые ответы пересчитаны
без новых LLM-вызовов. Изменились только шесть K21-проверок NA → PASS.
Первоначальные traces/checks/runner и исправленные checks/runner сохранены
в архиве отдельно. Содержательные verdicts и технические итоги не изменились.

Все 18 live-ответов прошли технические проверки: один Master call,
ноль domain tools, без fallback, в пределах latency threshold 60 s.
В текущей точке capture `actual_model` и `finish_reason` возвращаются null;
сохранены запрошенные model IDs и usage. Конкретный upstream не считается
зафиксированным. Денежная стоимость по счёту не измерялась.

например уровнем reasoning при том же prompt; этот результат не является
разрешением включить дополнительный verifier или переписывать методологию.
