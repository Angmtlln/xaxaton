# Проверка влияния истории: её удаления недостаточно

На текущей GLM ошибка оценки ресурсов воспроизводится и без предыдущих
ответов ассистента. Гипотеза «Master только повторяет ошибочную историю»
не объясняет все случаи. При этом величина влияния истории на частоту
ошибок данным экспериментом не установлена. Удалять историю в продукте
по результатам этой проверки не следует.

## Метод

Использован `z-ai/glm-5.3-flash`, без смены настроек модели, Risk Playbook
0.3.2 и runtime. Два исходных вопроса из `AGENT_EVALS.md` / scenario bank:
K19 и S15_10. Для каждого — три повтора в трёх условиях, всего 18 live-вызовов.

- **original:** исходная сохранённая история, включая прежние ошибочные выводы.
- **neutral:** каждый ответ assistant заменён на «Данные компаний получены.»;
  позиции сообщений и все вопросы пользователя сохранены.
- **absent:** удалены только сообщения assistant; предыдущие вопросы пользователя
  сохранены. Это абляция ответов ассистента, не совершенно новый разговор.

Trusted state, последний вопрос, user_context, last_answer_verified и
проверенные данные одинаковы. Нет synthetic overlay финансов. Для каждого
вопроса проверено побайтное равенство фактически отправленного system message
во всех девяти вызовах; там находятся методология и проверенный контекст.
Отличия касаются только assistant history. Все повторения одного варианта
имеют одинаковый вход; инструментальных и доменных вызовов нет.
Исходные вопросы и банк не упрощались. Это дополнительный диагностический
эксперимент на existing frozen replay, а не новый runtime.

## Что наблюдали

| Условие | Пример в S15_10 | Вывод |
|---|---|---|
| original | «источник текущих платежей по отчётности не виден» после нулевой выручки | В одном ответе не рассмотрены известные деньги и другие активы АПРЕЛЬ; остальные ответы тоже не дают полной оценки ликвидности |
| neutral | «ресурсов для крупных обязательств у компании нет» | Категорическое отсутствие ресурсов возникает без старого аналитического текста |
| absent | «крупных видимых источников платежа в балансе нет» | Ошибка возникает даже без единого прежнего ответа assistant |

У АПРЕЛЬ в переданном контексте активы 8,046 млн ₽: деньги 49 тыс. ₽,
дебиторка 647 тыс. ₽ и основные средства 7,35 млн ₽. Они не гарантируют
платёж, однако нулевая выручка их не отменяет. Сумма и срок конкретного
обязательства неизвестны, поэтому категорические ограничения для «крупных»
или «только небольших» платежей не обоснованы. В absent модель сама упоминает
основные средства, затем всё равно делает такой вывод. Это ошибка интерпретации,
а не только недоставленные факты или копирование прежнего ответа.

Дополнительная регрессия: во всех трёх absent K19 модель ответила заново
на предыдущие вопросы об устойчивости, кредиторке и количестве кредиторов.
Серия human-сообщений без ответов выглядит как несколько неотвеченных запросов.
Следовательно, этот способ очистки истории нарушает фокус разговора.
Это ограничивает трактовку absent; neutral сохраняет структуру обмена и
также воспроизводит целевой дефект.

Другие ошибки сохранены отдельно:

- original K19 повтор 1: «иски в сотни раз превышают собственный капитал»
  при 551% (около 5,51 раза), а также неверные 18 946 690 ₽ pending
  вместо 18 894 669 ₽.
- neutral S15_10 повторы 1 и 2: «в ~500 раз» и «в ~50 раз» вместо примерно
  пяти раз. Подобные числовые ошибки также возникают без старой аналитики.

Результат не доказывает, что история бесполезна или не влияет на модель.
Меняется весь предыдущий текст assistant, его объём и содержание; мы не
изолировали единственную ошибочную фразу. Три повтора на условие — малая
выборка, вызовы провайдера недетерминированы. Статистического вывода о
повышении/снижении частоты ошибок не делаем. Все ответы прочитаны coding
agent; независимого человеческого оценщика не было. В machine-readable review
выбранные наблюдения, не исчерпывающий semantic score.

## Практическое следствие

Не внедрять удаление истории как исправление этой ошибки. Промпт и доставка
фактов уже не предотвращают противоречащий им итог. Следующий проверяемый
кандидат — существующая ограниченная grounding-проверка существенных выводов
с одним repair и консервативным fallback. Её полезность пока **не проверена**:
в этом эксперименте verifier не включался и не добавлялся. До включения в
продукт нужен отдельный парный прогон, включая ложные срабатывания, пропуски,
стоимость и задержку. Дополнительная модель тоже может пропустить ошибку;
обещать устранение дефекта заранее нельзя.

## Проверки и файлы

Из `backend/`:

```bash
PYTHONPATH=. .venv/bin/python -m pytest tests/test_history_ablation.py tests/test_compare_models.py -q
```

**6 passed in 2.88s.** Новый тест проверяет изоляцию копий и изменение только
assistant history. Существующие тесты проверяют replay/источники и реальный
runtime без доменных вызовов. Live: 18/18 технических PASS, по одному Master
вызову, без fallback; это не semantic PASS. Prompt hashes сохранены в manifests.

```bash
PYTHONPATH=. .venv/bin/python -m evals.history_ablation --variant original --output evals/results/history-new-original
PYTHONPATH=. .venv/bin/python -m evals.history_ablation --variant neutral --output evals/results/history-new-neutral
PYTHONPATH=. .venv/bin/python -m evals.history_ablation --variant absent --output evals/results/history-new-absent
```

Рабочая логика, модель, промпт, UI, БД и legacy endpoints не менялись.
Миграция не требуется. Полный suite и браузер не запускались: это узкий
диагностический эксперимент. Вручную проверить цитаты и их интерпретацию
по полным ответам и контексту; включать новый режим в UI не требуется.

- `backend/evals/history_ablation.py`: воспроизводимый GLM-only CLI.
- `backend/tests/test_history_ablation.py`: инварианты эксперимента.

- [answers.md](answers.md): все 18 полных ответов.
- [runs.json.gz](runs.json.gz): manifests, frozen inputs, фактические сообщения,
  tool traces, usage, latency и исходник runner.
