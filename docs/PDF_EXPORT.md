# Экспорт результата в PDF

После полного анализа или сравнения кнопка **Экспортировать в PDF** сохраняет
конкретный ответ: вывод, карточки, графики, все строки сравнения, раскрытые
источники и новости, если они присутствовали. Затем **Скачать PDF** загружает файл.
Кнопка остаётся у исходного результата после следующих вопросов. Команда
«экспортируй это в PDF» сохраняет последний доступный результат; неоднозначная
ссылка требует выбрать кнопку нужного результата. Новый анализ не запускается.

## Контракты и границы

- `AssistantResponse.suggested_actions` дополнен backend-действием
  `{type: "export_pdf", label, result_id}`. Обычные `submit`/`compose` сохранены.
- `AssistantResponse.attachments` содержит описание PDF: `id`, `filename`,
  `mime_type`, `size_bytes`, `download_url`. Ссылку формирует сервер.
- `POST /api/v1/chat/{conversation_id}/exports`, тело `{result_id: UUID}`,
  возвращает описание PDF. `GET /api/v1/chat/{conversation_id}/exports/{file_id}`
  отдаёт файл с `Content-Disposition: attachment` и `Cache-Control: no-store`.
  404 означает отсутствующий результат/файл или истёкшую сессию; 503 при создании
  означает сбой генератора. Произвольный HTML и URL входом не поддерживаются.
- Capability `ExportStore.export_result_pdf` и LangChain-адаптер
  `build_export_pdf_tool` используют один генератор. Простая команда диспетчеризуется
  runtime без model call и без domain tools. Экспорт не изменяет LangGraph-контекст.
- Хранятся до шести неизменяемых снимков ответа на диалог (до 2 МБ каждый).
  PDF до 10 МБ создаётся по требованию и повторно используется. Временные файлы
  удаляются при вытеснении результата, очистке сессии или штатном завершении процесса.
  Очистка истёкших сессий, как в существующем ConversationStore, выполняется при
  следующем обращении. После перезапуска ссылки недоступны.
- Доступ ограничен существующей границей сессии: знанием непрозрачного
  `conversation_id`. Пользовательская аутентификация этой фичей не добавляется.
- DB impact: отсутствует. Изменены только API DTO и process-local хранение;
  SQL, repository и схема БД не менялись, миграция не нужна.

## Генератор

Python Playwright 1.58.0 и соответствующий Chromium. Печатная страница
`frontend/pdf.html` переиспользует `buildAssistantMessage`; отдельные CSS меняют
только экспорт. A4: анализ в портретной ориентации, сравнение в альбомной.
Таблицы не зависят от экранного фильтра. Текст остаётся текстом, SVG — вектором.
Сохранённая проза не получает дополнительной проверки или статуса grounded.

Все запросы Chromium перехватываются: разрешены только файлы из frontend,
никакого сетевого обращения к `/report`, backend API или внешним источникам.
Одна генерация одновременно на процесс, 30 секунд включая ожидание слота;
контекст и браузер закрываются при завершении/ошибке.

## Запуск и проверка

Dockerfile устанавливает браузер, системные зависимости и кириллические шрифты.
Для локального запуска после установки requirements:

```bash
cd backend
.venv/bin/python -m playwright install --only-shell chromium
# На Linux системные библиотеки: python -m playwright install --with-deps --only-shell chromium
PYTHONPATH=. .venv/bin/python -m pytest tests/test_pdf_export.py tests/test_chat_api.py tests/test_agent_runtime.py -q
PDF_TEST_OUTPUT=/tmp/aleph-pdf-test PDF_REAL_TEST=1 PYTHONPATH=. .venv/bin/python -m pytest tests/test_pdf_export.py -q
```

В команде выше каталог PDF и JSON задан через
`PDF_TEST_OUTPUT=/tmp/aleph-pdf-test`. Проверять текст и изображения страниц через Poppler/pypdf;
особенно пять колонок, длинные названия, кириллицу и многостраничные источники.
Тест использует фикстуры и не доказывает качество live-выводов модели.

Ручной desktop-сценарий: полный анализ → экспорт → скачивание; сравнение →
экспорт → скачивание; следующий вопрос → экспорт старого результата. Проверить
ошибку скачивания после истечения сессии. Legacy `/report` и мобильный UI
остаются без изменений.

## Приёмка 2026-09-06

Финальный Docker-образ проверен без внешней сети, с ограничением 1,5 ГБ RAM
и двух CPU для тестового контейнера. 143 теста прошли: PDF, chat API/runtime,
сравнение, multi-turn, кнопки и статусы. Реальный desktop-проход использует
fixture-данные, настоящий HTTP API, Chromium и скачивание файла; live-LLM
и подключение production-БД этим результатом не подтверждаются.

Отдельно извлечён текст PDF и сверены ИНН, названия, значения источников и
пробелы данных каждой компании. Проверены страницы отчёта, сравнений двух/пяти
компаний, график и четыре тестовые новости. Обнаруженную потерю содержимого
`details` на дальних страницах устранено превращением раскрываемых блоков
в обычные секции только внутри печатного документа.
