# Доступность данных Master

Проверено 2026-09-05 на **100 компаниях** из `contractors_audit.snapshot.json`.
[Инвентаризация всех 19 разделов](DATA_SOURCE_INVENTORY.md),
[предоставленная спецификация полей](GET_FULL_REPORT_FIELDS.md).
Исполняемые проверки: `backend/tests/test_data_coverage.py`.

## Путь и область данных

Сохранённый снимок → общие finance/legal builders и `data_sections.py` →
Pydantic ToolResult → `normalized_tool_context` → Master.
FC использует **тот же снимок**, что прочитан `run_check`: приватный
`_agent_snapshot` существует только в серверном ответе `include_summary=False`,
удаляется границей CheckResponse/ToolResult и не отправляется модели/API.
Legacy `/api/v1/checks` и `/report` сохраняют свой проход и контракт.

Компания, идентификатор снимка (если известен), дата отчёта и статус входят в
каждый нормализованный домен. Исходная `reportDate` и импортированная дата
сохраняются отдельно; расхождения не замалчиваются. Смена известного snapshot_id
или даты сбрасывает кеш остальных доменов. Evidence IDs одно-компанейского
результата локальны его компании/снимку; comparison префиксует их ИНН.

`status` описывает выполнение; `availability`, `gaps`, `field_states` и состояния
разделов — полноту. Даже успешный FC может иметь PARTIAL coverage. Агрегат legal
публикуется только при известных необходимых компонентах; отсутствие записей
не доказывает отсутствие события. Legacy суммы с подстановкой нуля не используются
в расширенной агентной проекции FC. Схема SQL и сохранённые данные не меняются:
добавлены поля **in-memory Pydantic-контрактов**, DB migration не требуется.

## Компактная карта source → Master

Все raw paths ниже начинаются с `report.`; все sections принадлежат компании
в окружающем ToolResult. `field_ref` у раздела и `source_index` у записи сохраняют
путь. Таблица описывает доступность, а не заполненность каждого снимка.

| Raw JSON | Значение / период | Builder → ToolResult → Master | Доступ и ограничение |
|---|---|---|---|
| `baseInfo`, `status.{status,reasonName,date}`, `reportDate`, `zskRiskLevel` | Идентичность, причина и дата статуса, два независимых статуса риска | `company_from_snapshot` → `company`, `sections.source_dates` → те же поля | FC/F/L/C; raw CURRENT может противоречить reasonName; сохраняются оба |
| `finReports[].common.{year,proceeds,profit}` | Год, выручка, прибыль/убыток, рубли | `build_financial_data` → `fin.series` и значения для UI → `series` | FC/F, C в `companies[].sections.finance_series`; прибыль не называется чистой |
| `assets.{totalAssets,currentAssets.*,uncurrentAssets.*}` | Активы, запасы, дебиторка, деньги/эквиваленты, внеоборотные/основные средства | `ALL_PATHS` → тот же финансовый ряд | Включая stocks/noncurrent_assets/fixed_assets сверх старого facts |
| `liabilities.{capitals,totalLiabilities,shortTermLiabilities.*,longTermDuties.*}` | Капиталы/резервы, **все пассивы**, обязательства и раскрытые части | `ALL_PATHS` → ряд | Включая borrowed_funds и long_term_others. Кредиторку не прибавлять к включающему её итогу |
| `coefficient` | Исходные коэффициенты и год | `sections.coefficients` | F / `section=finance`; названия известны, исходные формулы и единицы не раскрыты, не пересчитываются |
| `arbitrationCases[]` | Обе роли, количества/суммы, годы | safe legal builder + `sections.court_years` → структурированные rows | FC/L/C; нет длительности покрытия года, автоматическая годовая тенденция не вычисляется |
| `arbitrationByStatus` | Обе роли и Pending/Appealed/Finished | `sections.court_stages`, `legal_aggregates` | Структурированные значения, не разбор evidence display. Нет решений/предметов/исполнения; стадии не суммируются |
| `executionProceedings[]` | active/number/date/amount | safe legal aggregates + `sections.proceedings` | Даты по убыванию, 5 записей на страницу; total/included/offset/next_offset/truncated. amount не остаток |
| `inspections[]` | Орган, даты, вид, форма и исход проверки | `sections.inspections` + проверенные агрегаты | FC/L/C, дальнейшие страницы через L; нет подробных актов/штрафов |
| `reputationalRisks.{positive,negative}[]` | Описания, коды, главы и полярность | `sections.positive/negative/mass_okved_source` | FC / `section=signals` или profile. Это заявления источника, не автоматически доказанная интерпретация |
| `kindsOfActivityInfo` | Основной и дополнительные коды/описания | `sections.activity/activity_other/activity_count` | `section=activity`; massOkved существует в raw, его текст конфликтует с пояснением кейса. Количество кодов — отдельная величина |
| `baseInfo.{website,companySize,staff}` | Сайт из снимка, размер, персонал | `sections.profile` | FC / `section=profile`; staff отсутствует во всех 100 снимках; сайт не посещался |
| `licenses[]` | Название, статус, даты, орган | `sections.licenses` | FC / `section=licenses`; не доказательство ресурсов/исполнения |
| `procurements[]` | Год, закон, подписанные договоры/суммы, победы | `sections.procurements` | FC / `section=procurements`; подписанный ≠ успешно исполненный |
| `foundersInfo`, `relatedCompanies`, `branchesInfo`, `taxSystem` | Уставной капитал, корпоративные связи, филиалы, налоговые режимы | `sections.founders/connections/parents/branches/tax` | profile/connections; индивидуальные ИНН, ФИО, контакты исключены из модельного контекста; это частичная профильная проекция |
| `_id`, `baseInfo.{kpp,okpo,email}`, `phones`, персональные поля | Технические идентификаторы/контакты | Остаются в сохранённом snapshot | Намеренно исключены из аналитического prompt; причины по разделам в инвентаризации |

## Расчёты

`sections.calculations` и, при совместных finance/legal, `sections.claim_scale`.
Каждый элемент содержит formula, version, unit, value, state/reason и input_refs.
Входы один раз записаны в `section.inputs`: значение, исходный путь, год либо
область legal-агрегата и дата отчёта. Компания/снимок задаются окружающим company.
Повторы входов устранены для сохранения прежних лимитов ToolResult.

- Абсолютное изменение последних двух раскрытых периодов для выручки, прибыли,
  капитала, кредиторки, активов и дебиторки: `a-b`.
- Процентное изменение: `(a/b-1)*100`, только соседние годы и положительная база.
- Оборотный капитал: оборотные активы минус краткосрочные обязательства.
- Текущая ликвидность: их отношение при положительном знаменателе.
- Капитал к активам; дебиторка/деньги/запасы к оборотным активам;
  краткосрочные/долгосрочные обязательства к **всему пассиву**.
- Прибыль/убыток к выручке (не утверждение о чистой марже), кредиторка к выручке.
- Отдельно суммы требований к ответчику и активных ИП к активам, положительному
  капиталу и годовой выручке. Разные периоды явно помечены: это масштаб, не общий долг.

Ноль/отрицательный знаменатель, пропуск, invalid/nonfinite и несоседние годы
дают not_calculable с причиной. Округление 2 знака. Дата снимка не подменяет
год отчётности. Денежные единицы следуют текущему импорту; их внутренняя проверка
по 86 числовым/текстовым парам описана в инвентаризации.
Нет денежных потоков, сроков платежей, чистых активов по специальной методике,
остатка/предмета ИП, связи иск→решение→ИП, PD, DSO/DPO, DSCR и отраслевых порогов.
Условия сделки остаются user_context; отдельного проверенного калькулятора сделки нет.

## Проекции, чтение подробностей и comparison

F передаёт последние 5 уникальных лет по возрастанию, с исходными индексами и
состояниями каждого пропуска. Дубликаты года исключаются с предупреждением.
Весь снимок остаётся в repository. Параметры существующих F/L инструментов:
`inn`, optional `section`, `year`, `offset`; произвольные пути/SQL запрещены.
Имена sections перечислены в `DomainDataArgs`, доступные разделы — в
`sections.available_sections`. Примеры в чате: «Покажи лицензии ИНН…»,
«Покажи исполнительные производства ИНН…, страница 2», «Финансы ИНН… за 2024».
Одна страница требует максимум одного текущего domain call, без повторного FC.
Пагинация читает последний snapshot и возвращает его идентификатор/даты;
изменившийся снимок не смешивается с прежним кешем.

FC наполняет finance/legal trusted context, поэтому обычные вопросы по этим
доменам и «Почему?» повторного инструмента не требуют. Запрос другой страницы,
года или явно названного отдельного раздела делает ограниченное чтение через F/L.

C сохраняет тематические ряды, legal-стадии/детали и расчёты отдельно для каждой
компании. Для каждой табличной финансовой меры ищет общий заполненный год **во
всём локальном нормализованном ряду**, включая годы за пределами prompt-проекции.
Индивидуальные последние годы остаются отдельно; у каждой меры есть
`comparison_periods`. Нет общего года — отдельные годы и предупреждение,
не искусственно общая колонка «2025». Актуальные негативные факторы не откатываются.
Коэффициент изменения выручки остаётся индивидуальным и не получает общего года
по умолчанию; судебная полнота интервала неизвестна.

Покрытие 19 source-разделов не означает, что каждое вложенное поле включено в
каждый prompt: персональные данные и технические поля исключены, страницы и
периоды ограничены явно. Дополнительных LLM-этапов для извлечения данных — **0**.
