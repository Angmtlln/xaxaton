## Поведенческие результаты финального прогона

Ручная оценка по тексту v0.2, не новый online-verifier. Строгий критерий:
есть неподтверждённое существенное утверждение → сценарий FAIL.

| Сценарий | Результат | Неподтверждённый переход |
|---|---|---|
| Баланс | FAIL | Нулевая выручка названа «спящей» деятельностью; рост объяснён финансированием кредиторкой. Нет подтверждения деятельности/движения средств |
| Почему? | FAIL | Усиление до покупки всего в долг у поставщиков и невозможности оплаты при любом сбое; нет состава кредиторов и графика платежей |
| Судебная динамика | FAIL | Годы привязаны к Finished/Pending по совпавшим суммам; нет связи записей. Динамика трактуется как рост без сопоставимого покрытия интервалов |
| Comparison | FAIL | Финансовое состояние перенесено на надёжность поставки; обобщение периода до 2025, хотя общий год прибыли — 2024. Backend периоды и UI-ячейки корректны, проза не всегда следует им |
| Продаём с отсрочкой | FAIL | Роль понята, но повторена выдуманная связь года и стадии суда и порядок оплаты кредиторам |
| Покупаем с авансом | FAIL | Роль понята, совет увеличить аванс не дан; выручка объявлена доказательством операционной деятельности, последствия ограничения для поставки описаны слишком категорично |

Дополнительная граница: целевой legal-ответ может упоминать прежние финансовые
числа из истории; соседний проверенный домен гарантированно добавляется для
запроса условий сделки, не для любой возможной междоменной реплики. Отдельного
семантического контроля всей прозы эти изменения не создают.

[Три ответа и usage](benchmarks/playbook-v02-full.json): wall 38 990 / 43 038 /
19 346 ms, Master calls 1 / 1 / 1, tools 1 / 0 / 0, fallback=0.
Master input всего 29 284. Первый FC сохранил четыре существующих доменных Groq
вызова (9 375 prompt tokens суммарно); legacy Summary в chat не запускается.
Нового извлечения или LLM-этапа плейбука нет. Проверенный finance-контекст
повторно используется без второго FC и без targeted tool.

**Поведенчески набор тоже не принят:** ограничение ФНС превращается в запрет
любых платежей, общая положительная метка — в отсутствие банкротства,
исторический коэффициент восстанавливается при отсутствующих итогах баланса,
«риск выше среднего» появляется без бенчмарка. PARTIAL передаётся, но само
наличие этого статуса не предотвращает домысливание.

## Ограниченность итераций и воспроизведение

Сохранены и исключённые попытки: [ошибка импорта](benchmarks/playbook-v02-failed-import.json)
дала fallback из-за пропущенного импорта константы, исправлена;
[первый работающий вариант](benchmarks/playbook-v02-initial.json) показал
нехватку проверенного междоменного контекста для роли сделки и преувеличения.
После него выполнена одна ограниченная коррекция: передача соседнего trusted
домена и сохранение совместимых ограничений прежнего prompt. Затем выполнен
финальный набор выше. Дальнейшее улучшение формулировок не имитировалось
серией повторов. Неудачные попытки не учтены как успешное ускорение.

Для воспроизведения нужен настроенный текущий live provider; команды делают
оплачиваемые запросы. Из `backend/`:

```bash
PYTHONPATH=. BENCH_OUTPUT=/tmp/playbook-after.json .venv/bin/python scripts/benchmark_playbook.py
PYTHONPATH=. BENCH_MODE=full BENCH_OUTPUT=/tmp/playbook-full.json .venv/bin/python scripts/benchmark_playbook.py
```

Скрипт завершится ошибкой при fallback; поведенческий PASS он не устанавливает.
Baseline-артефакт получен на старом checkout тем же набором реплик; текущий
скрипт воспроизводит текущий runtime, а не прежнюю версию автоматически.

После запуска обновлённого backend вручную проверить чат и визуальное
отображение: баланс → «Почему?», судебные страницы, реальные годы comparison,
смену роли оплаты, пропуски/PARTIAL. Особое внимание — перечисленным FAIL:
**готовность ответов к рекомендациям по сделке не подтверждена**.
